# 知識カードの執筆ガイド

コンサル知識333（`data/knowledge/C01.json`〜`C13.json`）を書く・直すときの決まりごと。
目次の正本は `data/outline.json`。章・番号・タイトル・レベルは目次と完全一致させる。

## 1. 先に読むもの

- `skill/remake-consulting-skill/SKILL.md`（不変の品質条件）
- `skill/remake-consulting-skill/references/corrections.md`（誤読・一般化の修正。クイズの誤答選択肢の材料にもなる）
- 担当章に関係する `references/*.md`（workflow / playbook / templates / examples / video-map）
- `data/sources.json`（出典台帳108件。`remake` 参照の番号はここ）

## 2. 形式（1章 = 1ファイル = JSON配列、目次順）

```json
{
  "id": "C08-04",
  "chapter": "C08",
  "level": 1,
  "title": "顧客便益倍率V/Pと原価倍率P/Cを区別する",
  "summary": "価格Pを顧客の便益Vと比べる（V/P）か、自社の提供原価Cと比べる（P/C）かで意味が変わる。前者は顧客にとっての割に合う度合い、後者は自社の採算を表す。",
  "points": [
    "V/Pは顧客側の指標。大きいほど顧客にとって割に合う",
    "P/Cは自社側の指標。大きいほど粗利に余裕がある",
    "「3〜10倍」などの目安は検証用の仮置きで、普遍的なルールではない"
  ],
  "howto": [
    "便益V・価格P・原価Cを同じ期間（例：年間）にそろえる",
    "V/PとP/Cを別々の欄で計算する",
    "Vは保守・標準・楽観の幅で示し、根拠を書く",
    "どちらの倍率の話かを提案書に明記する"
  ],
  "pitfall": "「価格は顧客価値の3〜10倍」のように分子と分母を逆にすると、顧客に不利な価格を正当化してしまう。年間便益と月額料金を混ぜるのも誤り。",
  "example": "個人事業主Bさんの見積作業改善。年間の時間価値V＝36万円（標準）、料金P＝12万円、提供原価C＝6万円でV/P＝3倍、P/C＝2倍。時間価値は現金利益ではないと併記した。",
  "quiz": {
    "q": "顧客の年間便益V＝60万円、料金P＝20万円、提供原価C＝8万円。正しい説明はどれ？",
    "choices": [
      "顧客便益倍率V/Pは3倍、原価倍率P/Cは2.5倍",
      "顧客便益倍率は2.5倍、原価倍率は3倍",
      "価格が顧客価値の3倍なので適正",
      "V/Pが3倍なので成果は保証できる"
    ],
    "answer": 0,
    "explain": "V/P＝60÷20＝3、P/C＝20÷8＝2.5。倍率は採算や割安さの目安であり、成果の保証にはならない。"
  },
  "tags": ["価格", "数字"],
  "basis": "skill",
  "refs": [
    { "kind": "skill", "file": "playbook", "section": "E" },
    { "kind": "skill", "file": "corrections" },
    { "kind": "remake", "id": 90 }
  ]
}
```

| 項目 | 内容 | 目安 |
|---|---|---|
| summary | 何か・なぜ大事か | 1〜2文、60〜150字 |
| points | 要点 | 3件、各60字以内 |
| howto | 現場での使い方（命令形の手順） | 2〜4件、各80字以内 |
| pitfall | よくある誤り・使わない条件 | 120字以内 |
| example | 架空の適用例 | 160字以内 |
| quiz | 4択。暗記より場面判断を問う | 正解位置はばらす |
| tags | 短い分類語 | 1〜4件 |

文体は常体（〜する。〜しない。）。スマートフォンで読むので一文を短く。`「」` を使い、JSON内で `"` を使わない。

## 3. 架空例（example）

- RE:MAKE の支援領域に寄せる：AI導入支援、個人事業主・中小企業の業務改善、飲食店・店舗支援、NLPを使った対話・研修
- 人名・店名は架空（「個人事業主Bさん」「架空のカフェA」「居酒屋C店」など）。実在の店舗名・企業名・人物を使わない
- 例の数字は説明用。実績・相場・効果として書かない
- 「（架空）」の前置きは不要（画面側で表示する）

## 4. 出典（refs）と根拠区分（basis）

- `basis: "skill"`：主にRE:MAKEスキル（ユーザー提供の要約と一次資料監査の統合）に基づく。`remake` か `skill` の参照が必須
- `basis: "general"`：一般的なコンサルティング知識。原典との照合はしていない扱いになる
- `{ "kind": "remake", "id": N }`：台帳108件のうち、ラベル・動画タイトル・主題が明らかに対応するものだけ。こじつけない
- `{ "kind": "skill", "file": "playbook", "section": "E" }`：file は SKILL / workflow / playbook / templates / examples / corrections / sources / video-map
- `{ "kind": "book", "label": "著者『書名』" }`：著者と書名に確信がある有名書籍だけ。さらに読む手がかりであり、引用や頁の確認ではない
- `{ "kind": "web", "label": "…", "url": "…" }`：`data/sources.json` に載っているURLだけ。新しいURLを作らない
- 確信がなければ refs を空配列にし、`basis: "general"` にする

## 5. 内容の決まり（HANDOFF.md・corrections.md より）

- 顧客便益÷料金（V/P）と料金÷提供原価（P/C）を区別する。一律の価格下限（例：20万円以上）を書かない
- 売上＝客数×平均客単価。期間・税・値引き・分母をそろえる。改善レバーを足し算の式にしない
- 欠測をゼロにしない。観測できた期間と全期間を区別する。分母0の増減率は計算不可
- 導入前後の変化だけで原因・効果を断定しない（比較群・交絡を確認）
- 自由回答で探索し、仮説は確認質問で検証する。誘導質問だけにしない
- AIの文章・数値・引用を自動的に正しいと扱わない
- 作業時間の偽装、不要な納品遅延、不安の煽り、架空の期限・値引前価格を勧めない
- NLPは対話・学習の補助。治療・成果・人格変容を保証しない。心理類型で人を断定しない
- 法律・税務・医療・投資は確認事項を整理して専門家確認につなぐ。結論を断定しない
- 出典にない統計・倍率・研究結果を作らない。よく引用される経験則（70:20:10、80:20など）は「目安」と書く
- 「必ず」「保証」「絶対」で成果を約束しない

## 6. 検証

```bash
node scripts/validate.mjs C08     # 章を指定
node scripts/validate.mjs         # 全章
```

エラーは0にする。警告（文字数の目安超過など）はできる範囲で直す。
