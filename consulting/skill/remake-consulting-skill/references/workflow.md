# 実行フロー：ポリア式をコンサルティングへ

## 目次
0. 支援の合意／1. 理解／2. 計画／3. 実行／4. 振り返り／5. 分岐判断

## 0. 支援の合意
最初に以下を既知・仮置き・要確認に分ける。
- 欲しい成果：答え、意思決定、行動計画、理解、相談整理、自己変容
- 対象：事業、現場、対話、学習など
- 評価軸：速度、精度、再現性、安全、創造性、費用、負担
- 誰が決め、誰が実行し、誰が影響を受けるか
- 納期・予算・使える時間・データ・権限

「今日は何が決まると、この時間を使ってよかったと思えますか？」から始める。回答がすでにあれば要約して確認する。全項目を毎回問診しない。

## 1. Understand：問題を解ける形にする
### 1-1. 分離表
| 区分 | 記載内容 | 例 |
|---|---|---|
| 未知 | 意思決定に必要な答え | 日報作業を減らすにはどこを変えるか |
| 事実 | 観測と出典・日時 | 直近5回の作業記録 |
| 解釈 | 事実の意味づけ | 転記が多いように見える |
| 仮説 | 反証可能な説明 | 二重入力が所要時間の主因 |
| 条件 | 守る制約 | 既存会計ソフトを継続 |
| 行動 | 検証・実装 | 5回分を工程別に計測 |

### 1-2. 抽象語を定義する
「売上を上げたい」→誰の何の売上、いつまでに、どの基準か。
「忙しい」→どの作業、何回、何分、どの時間帯、他業務への影響か。
「不安」→何が起こる懸念か、観測できる兆候は何か、何が分かれば判断できるか。
感情そのものを間違いとして処理しない。感情と事実の両方を尊重する。

### 1-3. 聞く順序
自由回答で現状・具体場面 → 例と頻度 → 根拠・例外 → 影響 → 理想 → 試したこと → 制約 → 仮説を閉じた質問で確認。
誘導防止に「別の理由もありそうですか？」を添える。矛盾は詰問せず場面差・時間差を確かめる。

### 1-4. 課題の一文
「［対象］が［期限］までに［指標］を［目標］にするうえで、［制約］の下、［何を決めるか］」
目標値が未定なら勝手に確定せず、測定から始める。

### 品質ゲート
- 顧客が再定義に同意したか
- データで答えられる問いか
- 本当の依頼と代理指標がすり替わっていないか
- 根本原因を断定する前に代替説明があるか

## 2. Devise a Plan：複数の解決ルート
最低限、現状維持と実行案を比較する。重要判断ではA（運用改善）、B（既存ツール）、C（個別開発）など異なる仕組みの案を出す。

| 方法 | 使う場面 | 確認 |
|---|---|---|
| 類題 | 過去事例がある | 顧客・規模・条件の違い |
| 分解 | 問題が大きい | 要素の重複と漏れ |
| 特殊化 | 検証が難しい | 1部署・1業務で試せるか |
| 逆算 | 目標が明確 | 成功条件と失敗条件 |
| 視点変換 | 利害が衝突 | 経営・現場・顧客・将来 |
| 制約操作 | 行き詰まり | 本当の制約と慣習の区別 |
| 小さな実験 | 不確実性が高い | 少ない費用で何を学べるか |

採用理由は影響、実現性、費用、時間、安全性、運用負担で示す。点数の根拠が薄ければ順位を精密に見せない。

### 実験設計
仮説／対象／変更する要因／維持する条件／基準値／評価期間／成功基準／中止条件／責任者を先に決める。
導入前後比較は季節、客層、営業日、スタッフ、販促、値上げ等の交絡を確認。比較群がなければ「関連が見られた」にとどめる。

## 3. Carry Out：実行と検証
1. 合意済みの範囲を小さな作業へ分解
2. 担当者・期限・必要権限・受入条件を明確化
3. 中間成果を見せ、解釈のズレを早く修正
4. 実績と想定を比較し、実行の問題か仮説の問題かを分ける
5. 追加依頼は影響を示して範囲・費用・期限を再合意

「誰かがやる」「なるべく早く」「いい感じに」は完了条件にしない。
詰まったら、事実不足→理解へ、施策不適合→計画へ、権限不足→必要な承認へ戻る。

## 4. Look Back：成果と自走化
- 目標・安全・費用・負担を満たしたか
- 有利な数字だけを選んでいないか
- 顧客が支援なしで再現できるか
- 手順書、例外時の判断、記録方法、次回レビュー担当があるか
- 学びを「条件→行動→期待結果→外れる条件」の型で残す

満足度は重要だが、売上・利益・時間・品質・定着率とは別に測る。

## 5. 支援モードの切り替え
| 状況 | 優先する対応 |
|---|---|
| 目的が曖昧 | 傾聴・問い・具体化 |
| 方法を知らない | 教示・例示・選択肢 |
| 分かっているが動けない | 障害と最小行動を一緒に設計 |
| 人手・技術が不足 | 許可された代行・実装と引継ぎ |
| 専門的リスクが高い | 情報整理と専門家への確認票 |
| 検証しても改善しない | 仮説・測定・対象の見直し |
