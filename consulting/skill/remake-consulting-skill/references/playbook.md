# 実務プレイブック

## A. ヒアリングと診断
### 面談前
公開情報、許可された業績・業務資料、担当者の立場を調べ、「既知の事実／確認したい仮説」を分ける。現場観察は目的と時間を伝える。「評価ではなく業務を正しく理解するため、30分ほど見学してもよいですか？」は一例で、長さは状況に合わせる。

### 質問の道具箱
| 目的 | 言い回し |
|---|---|
| 具体化 | 最近それが起きた場面を一つ教えてください |
| 数量化 | どのくらいの頻度で、何分ほどかかりますか |
| 理由 | そうお考えになった根拠は何でしょうか |
| 例外 | うまくいったときは何が違いましたか |
| 影響 | 解消しない場合、誰にどんな影響がありますか |
| 願い | 理想的には、どんな状態になっていたいですか |
| 条件 | 何がそろえば実行できそうですか |
| 言葉の揺れ | 「基本的には」とのことですが、例外はどんな場面ですか |
| 理解確認 | 私の理解は〜です。違うところはありますか |
| 仮説確認 | 原因はAと考えましたが、Bや他の事情もありますか |
| 行動化 | 今日できる一番小さな一歩は何でしょうか |

「どんな・どうして・どのように」は質問の入口。「どうして」は詰問に聞こえる場合があるので「どういう経緯で」に変える。7W2H（誰・何・いつ・どこ・なぜ・誰向け・誰と・方法・数量等）は漏れ防止の道具であり尋問の順番ではない。

肯定的な主張には根拠・成立条件、否定的な主張には例外・可能になる条件を尋ねる。選択肢A/B/Cを出すときは「他の案」も残す。相手の役割、予算、評価制度、過去の失敗も背景として見る。

専門家として教える、診断して提案する、一緒に課題を探る、のどの立場にいるかを自覚する。知らないふり、決めつけ、顧客の言葉を借りた誘導を避ける。

## B. 論点と仮説
「何を決めるための調査か」を先に一文にする。重要な問いは少数に絞るが、3問などの数は目安。
良い仮説は、具体的、事実に根ざす、反証可能、意思決定につながる。

原因仮説：［問題］の主因は［原因］で、［観測］が支持する。ただし［代替説明］もある。
解決仮説：［変更］により［機序］を通じて［結果］が改善する。［条件］なら棄却・修正する。

分解方法：AとA以外、構造・数式、時系列・工程、既存フレーム、顧客に分かる分類。顧客が納得しただけではMECEと証明されない。分類の軸と粒度を揃える。
知識→理解→応用→分析→統合→評価という学習段階は研修設計の参考にし、記憶だけで「現場でできる」と判定しない。

## C. 提案と資料
1. 意思決定者と判断項目を確かめる
2. タイトルだけで筋が通るストーリーを作る
3. 手書きレベルの構成・図を作る
4. 数値・出典・図表を検証する
5. デザインを整える

用途別の型：短時間の判断→結論と根拠、問題解決→事実・解釈・行動、背景共有→SCR（現状・問題・解決）。
1ページ1メッセージを基本とし、タイトルに「だから何か」を書く。ただし推論を確定事実のように書かない。
比較表、工程図、数字の分解、色の役割、要点枠で視線を導く。ショートカットやテンプレートは制作補助であり、全資料を10〜20分で作れる保証ではない。
提案書は背景・目的、現状、課題、選択肢、推奨、期待効果、範囲、進め方、費用、リスク、受入条件、次の判断を含める。社内説明をする担当者のために1枚要約と想定質問を添える。

## D. 会議・合意形成
開催前：目的、今日決めること、議題、必要資料を共有。24〜48時間前は運用例で、緊急会議に固定しない。
論点ごとに報告・議論・意思決定を区別する。参加者の関心、権限、懸念、賛否を把握し、懸念を議題に入れる。
開催中：発言を目標・現状・問題・解決策へ整理。リアルタイム議事録で確認する。「現場運用の観点ではどうですか」と観点を指定して全員の知見を引き出す。
異論は歓迎するが衝突自体を目的にしない。「この案が失敗するとしたら？」で安全に反証を出す。偉い人の発言も論点と根拠で検討し、人格を攻撃しない。
最後：決定事項、保留と理由、担当、期限、次回の論点を読み合わせる。最終案だけでなく途中の仮説と選択理由も共有する。

## E. 価格・商品・スコープ
### 価格の3つの視点
- 顧客：増益、費用削減、時間、品質、安心、リスク低減。ただし便益を二重計上しない
- 自社：実行工数、外注、ツール、管理、営業、修正、保証対応、稼働率、利益
- 市場：対象顧客、代替手段、予算、競合、調達条件

費用がC、必要粗利率がgなら売価P=C/(1−g)。gの対象に含める費用を定義する。時給は販売形態に採用しなくても自社採算の管理に必要。

価値倍率は「顧客の便益V÷支払総額P」。V/P=3〜10を置くなら仮説・検証用目安で、普遍的ルールではない。年間便益と1か月費用を混ぜない。保守・標準・楽観の幅を出す。

料金形態：範囲明確→固定、探索段階→時間枠または診断パック、継続変化→顧問、境界を見せる→段階プラン。固定価格でも達成保証や前払いが必須とは限らない。
「時給は？」への例：「今回は業務範囲と納品条件を決めた固定価格でご提案できます。まず目的と範囲を確認してもよろしいですか？」

値下げ要請には範囲・納期・支援方法を調整して選択肢を示す。一律高額化しない。3案は価格を吊り上げるためでなく、支援範囲の違いを理解して選べるようにする。
顧問契約では月次の論点前進、成果・変化の可視化、未整理の悩みの整理を設計する。更新価値と解約の分かりやすさを両立する。

### 合意事項
成果物／含む・含まない／顧客の協力／修正回数／検収基準／変更手続／料金・支払時期／中途終了／データ管理／既存知財と納品物の利用権を整理し、法的条項は専門家に確認する。
目標KPIと保証を区別する。追加要望には「当初範囲への影響を整理して、費用と納期を確認しましょう」。

## F. 集客と一人コンサル事業
対象顧客・重要課題・代替手段・強みを決める。資格やAI名より「誰の何をどう改善するか」を平易に伝える。
情報発信→相談→診断→小さな実証→実装→伴走という入口を作る。無料相談からの契約だけに固定せず、診断を有料商品にしてよい。
見込み客は連絡可能性、課題、時期、次の接点で管理する。「常に10社」や特定の競合社数は個人の目安で自社の成約率・稼働から決める。
受注期待額＝案件金額×見込み確率は予測であり売上実績ではない。紹介・発信・提携等に過度依存しない。
顧客との相性は目的・実行体制・約束・意思決定・支払条件で確認。人格の良し悪しと混同しない。

## G. 店舗・SV・KPI
売上＝客数×客単価。客単価＝1人当たり注文点数×平均1点単価（集計定義を揃える）。新規・再来は分類が排他的なときに客数として加算できる。
入口改善と提供体験の両方を見る。QSC（品質・接客・清潔さ）が弱いまま集客だけを増やすと期待との落差が生じ得る。
FL比率＝食材費率＋人件費率は同じ期間・売上基準で計算。60%やロス5%は業態共通の合否ではない。商品構成・家賃・利益構造に合わせる。
KGIは到達成果、CSFは重要成功要因、KPIはその状態や行動を測る指標。主要ボトルネックに集中しつつ、安全・品質・利益の監視指標を捨てない。
日次で事実、週次で変化と次の一手、月次で成果と資源配分を確認する。

SVは店舗目標、問題解決、資源配分、店長育成、士気を支援する。肩代わりだけで終わらず、現場観察→面談→優先順位→実行→証拠→確認者の流れを作る。
競合店（顧客が比較する選択肢）とモデル店（学びたい事例）を分ける。立地、規模、ブランド、商品、販促、接客、価格、固定客化を比較する。採点は根拠と観察日を残す。

## H. AI導入・教育・自走化
AIへ渡す仕事を目的、対象者、入力、制約、出力、評価方法に分解する。
得意分野候補：整理、たたき台、仮説、比較、文章調整、ロールプレイ。人間の検証：出典、数値、現場事情、権限、重要判断、責任分担。
「保守的な財務担当の視点で、提案の弱点と確認事項を出して」など反対意見の役割を使う。ただし演技したAIは専門家の実査ではない。
複数AIの利用は工程の必要性で決め、全AIを毎回使わない。既存契約・入力量・運用費・手戻り・情報露出を含む総費用で評価。
研修は説明→実演→実習→フィードバック→現場課題→振り返り。できた例だけでなく誤りを見抜く練習を入れる。
NLPの言い換え、観点変更、成功体験の振り返り等は本人の同意と選択の下で使う。心理状態を断定せず、治療・診断・記憶の真偽の判定に使わない。
公的伴走支援の対話・傾聴・自走化、ローカルベンチマークの財務と非財務の両面は補助枠組みとして使用。シートを埋めることを目的にしない。

## I. 独立・契約前後の運営
案件の入口を直請け・紹介・エージェント等に分け、単価だけでなく営業負荷、回収条件、裁量、利益相反を比較する。エージェントだから支払確実とは断定せず契約相手と支払条件を確認する。
独立準備では提供商品、対象顧客、稼働上限、見込み客、請求・契約の雛形、入金予定、保険・税務等の相談先を一覧にする。法人化や税務の結論は個別条件を専門家に確認する。
支払サイト、着手条件、中間確認、知財、解除時精算を契約前に整理。短期で抜ける必要が生じたら、理由、未了範囲、引継ぎ、金銭精算の確認事項を明文化する。契約上の権利を勝手に確定しない。
顧問の値上げは実績と支援範囲を可視化→新プラン→代替案→説明準備の順で検討。初年度割引なら適用期間・通常料金・更新条件を明確にする。解約金を一律3か月とする例は採用しない。
既存の方法論・再利用部品と顧客固有成果物を区別し、権利・利用条件を専門家と確認する。助言か制作かによる契約分類や印紙の要否を、この資料の一般論だけで決めない。
